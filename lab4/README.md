# Лабораторная работа 4: Синхронизация потоков

## Описание

Эта лабораторная работа демонстрирует различные проблемы синхронизации потоков и способы их решения.

## Структура проекта

### 1. Обедающие философы (Dining Philosophers)

#### `DiningPhilosophersWithDeadlock.cs`
- **Проблема**: Демонстрирует классическую проблему взаимоблокировки (deadlock)
- **Причина**: Все философы берут левую вилку, затем пытаются взять правую. Когда все философы взяли левую вилку, возникает deadlock
- **Использует**: `lock` (Monitor)

#### `DiningPhilosophersWithoutDeadlock.cs`
- **Решение**: Использует `SemaphoreSlim` для ограничения количества философов, которые могут есть одновременно
- **Механизм**: Семафор стола позволяет максимум 4 философам есть одновременно, что гарантирует, что хотя бы один философ сможет взять обе вилки
- **Использует**: `SemaphoreSlim` для вилок и семафор стола

### 2. Спящий парикмахер (Sleeping Barber)

#### `SleepingBarber.cs`
- **Описание**: Моделирует работу парикмахерской с ограниченной очередью
- **Механизм**:
  - Парикмахер спит, когда нет клиентов
  - Клиенты приходят и занимают места в очереди
  - Если очередь полна, клиент уходит
  - Клиент будит парикмахера, если тот спит
- **Использует**:
  - `SemaphoreSlim` для синхронизации парикмахера и клиентов
  - `Mutex` для защиты доступа к очереди
  - `ConcurrentQueue<int>` для потокобезопасной очереди клиентов

### 3. Производитель-Потребитель (Producer-Consumer)

#### `ProducerConsumer.cs`
Реализованы два варианта решения:

##### Вариант 1: BlockingCollection
- **Преимущества**: Готовое решение, простое в использовании
- **Механизм**: `BlockingCollection` автоматически блокирует производителей при переполнении и потребителей при пустом буфере

##### Вариант 2: SemaphoreSlim + lock
- **Преимущества**: Больше контроля над процессом
- **Механизм**:
  - `SemaphoreSlim` для отслеживания свободных и заполненных мест
  - `lock` для защиты критической секции (доступ к очереди)
  - Производитель ждет свободного места, потребитель ждет заполненного места

## Ключевые концепции

### Deadlock (взаимоблокировка)
Ситуация, когда два или более потока заблокированы навсегда, ожидая друг друга.

### SemaphoreSlim
Семафор ограничивает количество потоков, которые могут одновременно получить доступ к ресурсу.

### Mutex
Взаимоисключающий объект, который позволяет только одному потоку получить доступ к ресурсу.

### BlockingCollection
Потокобезопасная коллекция, которая автоматически блокирует операции при переполнении или пустоте.
